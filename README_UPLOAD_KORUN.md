# Module ৩ (Products) — আপলোড নির্দেশনা

## ১. এই ফোল্ডারের সবগুলো ফাইল GitHub repo (MehediVibeCoding/Mehediadmin)-এ
ঠিক এই একই folder path বজায় রেখে আপলোড/কমিট করুন (drag & drop দিয়ে পুরো
ফোল্ডার স্ট্রাকচার একসাথে আপলোড করা যায়)।

## ২. একটা পুরনো ফাইল ম্যানুয়ালি ডিলিট করতে হবে
`app/page.tsx` (রুট ড্যাশবোর্ড পেজ) নতুন জায়গায় সরানো হয়েছে:
**পুরনো:** `app/page.tsx`
**নতুন:** `app/(admin)/page.tsx`
GitHub-এ আপলোডের পর পুরনো `app/page.tsx` ফাইলটা ম্যানুয়ালি ডিলিট করে দিতে
হবে — নাহলে দুটো ফাইলই থেকে যাবে এবং build এ কনফ্লিক্ট হতে পারে।

## ৩. Supabase Storage bucket চেক করুন
`product-images` নামে একটা public bucket থাকতে হবে (ছবি আপলোডের জন্য)।
Supabase Dashboard → Storage-এ গিয়ে দেখুন এটা আগে থেকেই আছে কিনা
(legacy admin panel একই বাকেট ব্যবহার করত)। না থাকলে বানিয়ে নিন —
public access on.

## ৪. build ভেরিফাই করা হয়েছে
`npm run build` লোকালি চালিয়ে (placeholder env দিয়ে) কনফার্ম করা হয়েছে —
TypeScript এরর নেই, compile সাকসেসফুল। আসল Supabase কানেকশন ছাড়া রানটাইম
টেস্ট করা সম্ভব হয়নি — তাই Vercel deploy-এর পর একবার হাতে-কলমে (প্রোডাক্ট
যোগ/এডিট/ডিলিট/ড্র্যাগ-সর্ট/ছবি আপলোড/AI Parser) চেক করে নেওয়া ভালো।

## ৫. এই মডিউলে যা যা সিদ্ধান্ত/পরিবর্তন হয়েছে (সংক্ষেপে)
- ৬টা hardcoded default প্রোডাক্ট সিস্টেম বাদ — `custom_products` টেবিলই
  এখন একমাত্র সোর্স অফ ট্রুথ (আপনার অনুমোদিত সিদ্ধান্ত)
- "Extra Products পরিষ্কার" (broom) ফিচার তাই বাদ — ওটা শুধু ডিফল্ট
  সিস্টেমের জন্যই ছিল
- ছবি আপলোড আসলে বাস্তবে কাজ করানো হয়েছে (legacy-তে ফাংশন ছিল কিন্তু কোনো
  বাটনের সাথে যুক্ত ছিল না — dead code)
- `closing` কলাম এডিটের সময় touch করা হয় না (legacy বাগ এড়াতে — নাহলে
  এডিট করলে বিদ্যমান closing টেক্সট মুছে যেত)
- AI Parser থেকে ক্যাটাগরি auto-select হয় না (legacy-ও করত না) —
  ম্যানুয়ালি বেছে নিতে হবে
- `danger`/`warn` রঙের টোকেন যোগ হয়েছে (tailwind.config.ts + DESIGN_SYSTEM.md)
- একটা basic Sidebar/nav শেল যোগ করা হয়েছে যেহেতু Module ১/২ এখনো তৈরি হয়নি
  — বাকি নেভ আইটেম "শীঘ্রই" ট্যাগসহ disabled অবস্থায় দেখাবে
